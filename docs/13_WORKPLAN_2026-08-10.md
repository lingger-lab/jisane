## 3.5 검증·완료기준 (Definition of Done)

> 원칙(verification.md): **fresh 실행 증거 없이 완료 주장 금지.** 각 항목은 아래 게이트를
> 통과하고, 커밋 메시지에 실제 실행 결과(“tsc 0 / vitest N passed / 의사환경 26개 clean”)를 명시한다.
> 완료 상태는 DONE / DONE_WITH_CONCERNS / BLOCKED 중 하나로, 미검증·스텁을 함께 disclose.

**공통 게이트 (모든 배치):**
- `tsc --noEmit` 0 (변경 앱/패키지 전부) · `eslint` 0(변경분) · `npm test` green.
- **회귀 점검(surgical)**: 변경 함수의 **호출자 전수** 확인 + **정상 경로 불변** 논증(동작 변화가
  의도 범위에만 국한되는지). 예: CAS는 정상 단일경로 1행 매칭 유지, 동시성 상황만 변경.

**유형별 추가 검증:**

|---|---|---|
| 동시성·금전(Batch B, §0 P2-50) | **red-green 회귀 테스트**: 가드 제거→실패, 복원→통과 확인. CAS 0-row(경쟁 패배) 동작 테스트 | 가드 on/off 각각 vitest 출력 |
