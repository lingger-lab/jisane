# 수익모델 전환 — 매칭비(거래 수수료) → 구독 기반 (2026-08-12)

> 의뢰인(박희중 이사) 확정 방향. 기존 "거래별 매칭비 + 7구간 단가 + 보증적립금(매칭비 10%)"
> 모델을 **구독 기반**으로 전환한다. 감사 의사결정 P3-17(수수료 용어)·P2-11(7구간 요율표)은
> 이 전환으로 **대체(무효)** 된다.

## 새 수익모델 (원문 기준)

1. **기업회원 구독료** — 월 **18,000원**(VAT 별도). 가정: 100개사 → **월 180만원** 수익.
   - 구독 기반: (1) S/W·P/G 사용(파트너업체·시니어지식인이 제공), (2) 부가로 시니어지식인
     정보를 **무료 열람·연락** 가능.
2. **시니어지식인 구독료** — 월 **9,000원** 납부 시 S/W·P/G 사용 가능.
3. **파트너(전문가) 회원 수익 배분** — 파트너가 플랫폼을 이용해 얻는 수익 중 **20%**.

→ **거래별 매칭비 폐지.** "매칭비 7구간 단가"·"매칭비의 10% 보증적립"·"중개 수수료" 개념 제거.

## 영향 범위 (전환 시 손대야 할 곳 — 초안)

| 영역 | 현재(매칭비 모델) | 전환 방향 |
|---|---|---|
| 코드 `packages/shared/lib/pricing.ts` | `calcMatchFee`(7구간)·`calcGuaranteeFee`(매칭비10%) | 매칭비 계산 제거 / 구독 과금 로직 신설 |
| 정산 `cap-pricing`·`auto-settlement`·settlement 스키마 | workFee+matchFee=total_pay, 에스크로 정산 | 거래 정산 구조 재정의(구독은 별도 빌링) |

## 처리 방침 (HARD-GATE)

- 이 전환은 **아키텍처·DB 스키마·결제 인프라 변경**(3+파일·신규 기능)이라 **선(先)설계**가 필요하다
  (golden-principles #7). 코드를 바로 뜯지 않는다.
- **P1-9/P1-17(결제 원자성) 설계 보류와 연동** — 어차피 "결제관계 설정 후" 진행 예정이므로,
  **구독·결제 인프라 설계와 함께** 다루는 것이 자연스럽다(docs/14).
- 우선 저위험·가역인 **공개 페이지 카피**만 구독 프레이밍으로 먼저 정리할 수 있으나, 요금·정책
  문구는 법적/영업 문서라 확정 문구를 받아 반영한다.

## 감사 항목 상태 갱신

- **P3-17(수수료 용어)·P2-11(7구간 요율표)**: 본 전환으로 **대체** — 매칭비 통일/공개 대신 구독
  모델로 재작성 대상. (기존 "의사결정"에서 "설계·재작성"으로 이동)
- **P2-12(개인정보 책임자)·P3-22(전자상거래 고지)**: 사용자 결정 **"나중에"** — 통신판매업 신고·
  담당자 실명 확정 후 반영(보류).
