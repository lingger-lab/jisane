### P1-1. Assign button has no in-flight state — double-click can create duplicate matching
- `apps/admin/app/(protected)/dashboard/matching-tab.tsx:266` · feedback · ☐ untaken
- handleAssign awaits createMatching/selectCandidate but the button is never disabled and shows no busy label during the request. Two rapid clicks both pass the server's status==='open' check (both read before either writes), so a duplicate matching can be created; meanwhile the admin gets zero feedback that anything is happening. Every other mutating button in this dashboard (dispute resolve, inquiry close, partner approve) disables itself while busy — this one, the highest-stakes action in the tab, does not.

### P1-6. Viewport blocks pinch-zoom on a seniors-targeted app (WCAG 1.4.4)
- `apps/expert/app/layout.tsx:35` · a11y · ☐ untaken
- maximumScale: 1 prevents users from zooming the page on browsers that honor it. This product's primary audience is explicitly senior experts, for whom text zoom is a core need; capping scale at 1 is a WCAG 2.1 AA 1.4.4 (Resize Text) failure on the exact user group most likely to rely on it. Remove maximumScale (initialScale alone is enough to prevent the iOS input-zoom jump if inputs are >=16px).

### P1-7. Expert search silently returns 0 results for terms containing parentheses (e.g. "(주)")
- `apps/owner/app/(browse)/experts/page.tsx:73` · states/effort · ☐ untaken
- The search term is interpolated into a PostgREST .or() filter string with only % and , stripped. Parentheses are NOT stripped or quoted, and they are structural in PostgREST's or= logic-tree syntax. A user searching "(주)지사네" — the standard Korean corporate prefix — produces `name.ilike.%(주)지사네%` whose `)` terminates the or-group early, the query 400s, the error is discarded (line 77 destructures only data), and the page renders as if zero experts matched. A very plausible input class silently fails with a fake empty state and no error feedback.

### P1-10. maximumScale: 1 blocks pinch-zoom (WCAG 1.4.4 failure)
- `apps/owner/app/layout.tsx:35` · a11y/WCAG AA · ☐ untaken
- The viewport export sets maximumScale: 1. iOS Safari ignores it, but Chrome on Android honors it and disables pinch-zoom entirely, failing WCAG 2.1 AA 1.4.4 (Resize Text, requires up to 200% zoom). For a platform whose brand is senior expertise, low-vision users being unable to zoom is a real exclusion. Remove maximumScale (initialScale: 1 alone is sufficient to prevent the input-focus auto-zoom this is usually added for, given inputs use >=16px text).
